Introduction

My first artifact, the Machine Learning Algorithm Framework, helped readers choose the right algorithm for a problem. This artifact goes inside one of those algorithms. Neural networks power image recognition, translation and chatbots, but most explanations either stay too shallow or jump straight into equations. I wanted to show what each part of a network does, how the parts work together, and what actually changes when you adjust them.

Description

The artifact is a 21-slide presentation in four parts:

  1. Introduction: an About Me slide, a project description (context, challenge and solution) and a data-flow diagram that follows a training step from the input layer through the hidden layers to the output, the loss and back again.
  2. The six components: one slide each for layers, neurons, weights and biases, activation functions, loss functions and optimization algorithms. Every slide pairs a definition with a diagram or formula and a result from my own experiments.
  3. Classification: a concept map of the four groups, a comparison chart of all six components and a slide that explains how I sorted them.
  4. Experiments and summary: the results of 20 network setups in TensorFlow Playground, a one-page results table and a summary of why visualizing neural networks matters.

Objective

The goal was to clearly define each key component of a neural network, illustrate its role visually and explain complex ideas in a way that a non-specialist can follow. A second goal was to support every claim with evidence from hands-on experiments instead of repeating textbook statements.

Process

  1. Hands-on exploration. I trained models in TensorFlow Playground and changed one setting at a time: the dataset, the noise level, the input features, the number of layers and neurons, the activation function and the learning rate.
  2. Making the experiments fair. A network can get lucky or unlucky with its random starting weights, so I trained every setup five times and reported the median. To log exact numbers, I ported the Playground’s open-source training code to Python and kept its defaults: 500 points, a 50/50 training and test split, batch size 10 and a learning rate of 0.03.
  3. Classifying the components. I grouped the six components by the question each one answers and tested that grouping against a second rule, as described below.
  4. Designing the slides. I used one idea per slide, a consistent heading layout and the Playground’s own blue and orange colors, so the charts match what readers see in the tool.
  5. Review. I checked every number against the saved results, rendered every slide to confirm that nothing overlapped, and proofread all of the text.

How the Components Were Classified

I sorted the six components by function, meaning the question each one answers in a training step:

  • Structure (layers and neurons): what the network is made of.
  • Parameters (weights and biases): what the network learns.
  • Transformation (activation functions): how each neuron shapes its signal.
  • Training (loss functions and optimizers): how the network improves.

I then checked each component with a second test: is it learned from data, or chosen by the designer? Only the weights and biases are learned. Everything else is a hyperparameter, which is exactly why each one could be tested in the Playground. I considered grouping the components by forward pass and backward pass instead, but I rejected that option because weights and activations are used in both passes, so a single component would land in two groups. My experiments follow the same grouping, with one extra group for the data and input features.

Key takeaway: a neural network is a set of simple parts that learn together. The right input features, enough capacity, a non-linear activation and a sensible learning rate matter more than any single component on its own.

Value Proposition

This artifact shows that I can understand a model from the inside, design fair experiments to test it, and explain the results visually to people who do not write code. These are the same skills I rely on at work when I turn complex rules into tested system logic and explain my changes to other teams.

Unique Value

Most introductions to neural networks define the components and stop there. This presentation goes further in three ways. It backs every component with a measured result from 100 training runs. It classifies the components into four groups and explains the reasoning, including the edge cases. And it shares the code, so anyone can reproduce every number and chart.

Relevance

Every modern AI system, from image classifiers to large language models, is built from the same components covered here. Knowing how layers, activations, loss functions and optimizers interact makes it easier to debug a model that will not train, choose sensible settings, and explain a model’s behavior to stakeholders. This presentation will also serve as my own reference as the program moves into deeper models.
